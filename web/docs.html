Getting started

Requirements: Linux (Ubuntu 22.04+ / Debian 12+), Docker for container servers, Go 1.21+ and Node 20+ only if building from source.

docker run -d --name kspanel -p 8080:8080 \
  -v kspanel-data:/data ghcr.io/your-org/kspanel:latest
# open http://YOUR-IP:8080 → create admin user

From source: git clone … && bash rebuild.sh && ./release/kspanel. The rebuild script builds the Vite frontend, embeds it into the Go binary, syncs the page/theme libraries and stamps release/version.json.

Configuration

Panel settings live in the UI (Settings) plus a small env file for DSN/port. Key knobs:

AreaWhat
Brandingpanel name, logo (5 MB), footer text, global theme
Auth policyregistration toggles, OAuth ×5, TOTP, lockout, session lifetime/idle
SecurityRPM limits, IP allow/deny, DDoS auto-stop, max body size, SMTP/TLS
DatabaseSQLite / Postgres / MySQL, live engine switch, backups + S3

Node setup

Each game host runs ksedge (default :4040). Create the node in Nodes → New, then either Setup local (same box) or run the agent remotely with the shown token. Modes: direct, reverse_tunnel (NAT), local_port, local_wss.

./ksedge --panel https://panel.example.com --token <TOKEN>
# check: curl http://node-ip:4040/health → {"status":"ok"}

Enable the drivers you need per node (docker / kvm / lxd / multipass), set alloc caps + overcommit, then watch heartbeats turn green.

Templates

Templates are blueprints (kind: docker|lxd|kvm|multipass) with 40+ spec fields: ports, mounts, limits, env, install steps, actions, healthcheck, labels, runtime (vCPU, machine q35/virt, UEFI, TPM, disks…). Create in Templates → New (8-section builder), import via file/URL, or POST /api/templates/url (SSRF-hardened).

spec:
  kind: docker
  image: itzg/minecraft-server:latest
  ports: [{container: 25565, protocol: tcp}]
  env: [{key: EULA, value: "TRUE"}, {key: MEMORY, value: 4G}]
  install:
    - run: eula=true
  actions:
    - id: start-java
      run: java -Xmx4G -jar server.jar nogui

Instance pages

Per-server custom tabs authored once as YAML in instance_pages/pages/*.yaml, linked into templates, snapshotted into instances. Content types: html (sandboxed iframe), markdown, blocks (no-code rows), react. Actions run on Edge via allow-list (shell / read_file / write_file / list_files / docker …) through window.KSPageSDK.

slug: files
name: Files
content_type: blocks
# + actions: / sub_pages: / components: — see instance_pages/GUIDE.md

Themes

Themes → Studio edits 15 tabs live (accent, background image/video/gradient, buttons, cards, sidebar, typography, loading…). Scope globally or per area/page, add custom CSS, publish to the marketplace, roll back via revisions. White-label via authority branding.
