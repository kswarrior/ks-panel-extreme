## Legend

- **IMPLEMENTED** — code exists, wired in router/scheduler, and exercised by frontend/backend. Includes security and tiny hardening details.
- **IN PROGRESS / PARTIAL** — code exists but not fully wired, or UX/policy still being refined. Behaviour is reachable but not final.
- **PLANNED** — design exists or stubbed, no complete implementation.
- **DEFERRED / NOT PLANNED** — explicitly deferred or rejected (no code, kept for transparency).

## IMPLEMENTED — Backend (panel/backend)

### A. Auth & Account Lifecycle

1. **Login / Logout** — `POST /api/auth/login` bcrypt + `POST /api/auth/logout` clear `__Host-session_id` + invalidate via `internal/auth/session_manager.go`. `panel/backend/internal/api/handlers/auth_handler.go:61`
2. **Multi-account switch-login** — `POST /api/auth/switch-login` returns token in body without clobbering cookie (`panel/backend/internal/api/handlers/auth_handler.go:246`). Frontend `Header.tsx` switcher + `useAuthStore` re-hydrate via `GET /api/me`.
3. **Self-service registration** — `POST /api/auth/register` respects `register_allow` / `verify_required` KV, email regex `^[^@\s]+@[^@\s]+\.[^@\s]+$`, bcrypt, async activity log. `auth_register_handler.go`
4. **Email verification (OTP)** — `POST /api/auth/send-verify` (code) + `POST /api/auth/verify-email` (token) via `email_verification_codes` table + `repository.SmtpSender`, TTL `consumed_at`. `016_email_verification` migration.
5. **Per-device account limit** — `device_registrations(id,device_id,user_id,email)` + long-lived device cookie `GET /api/auth/device-id` (`017_device_registration`). Frontend `Register.tsx` mints device id; register checks limit.
6. **Public auth flags** — `GET /api/auth/flags` (register_allow / verify_required) lets login page render “Create account” link unauthenticated. `handlers/auth_register_handler.go`
7. **OAuth / Social login** — 5 providers `google|microsoft|apple|discord|github` via `internal/oauth`. Endpoints `GET /providers`, `GET|POST /{provider}/start|callback` (Apple `form_post` POST fallback), state param, issues standard session cookie on success. `oauth_handler.go:47` wired in `server.go:133`
8. **Password policy + history** — `internal/auth/password_policy.go` + `password_history(id,user_id,password_hash bcrypt)` (043), reuse check on `PUT /api/me/change-password`, `ChangeUsernameHandler` separate. Frontend `Account.tsx` enforces.
9. **Account lockout** — 5 attempts / 15 min per IP+user, in-memory map `internal/auth/account_lockout.go` + admin `GET /unlock` + `POST /unlock` (`authentication_admin_handler.go:18`), gated `ACCESS_ADMIN_PANEL`.
10. **Recovery codes (MFA)** — `recovery_codes(id,user_id,code_hash bcrypt,used,created_at)` (043), `GET /generate` + `POST /generate|consume` (`authentication_admin_handler.go:53`), bcrypt, single-use.
11. **Session manager** — `internal/auth/session_manager.go` + `session_policy.go`: `__Host-session_id` HttpOnly, `SameSite=Strict`, `Secure` (forces HTTPS except `localhost:5050`/`127.0.0.1:5050`), sliding expiry at `< lifetime/2`, `TrackedSessionValid` revocation, `Lifetime 480m / Idle 1440m / MaxPerUser 0` via `042_security_tabs` KV, `isDevelopment()` vs prod.
12. **Auth middleware** — `internal/api/middleware.go:AuthMiddleware` — `Authorization: Bearer` wins over cookie (multi-account), `ValidateSessionToken` + `MaxAge` vs `CurrentSessionPolicy().Lifetime`, per-request `IsUserSuspended` DB check, context `UserIDKey` + `expiryKey`, rotation via `SetCookie`. `extractBearerToken`, `MustAuth`, `normalizeClientIP` brackets strip.
13. **Rate limiting (auth)** — `internal/api/rate_limiter.go` in-memory `clientID -> []time.Time` + `RWMutex` + janitor 5 min purge>15 min, `loginAttempts=5/15m` + `registerAttempts=3/1h`, `Retry-After` + `X-RateLimit-Remaining` headers. Separate from `security.State` persistent limiter.
14. **User suspension** — `users.suspended,suspended_until,suspension_count,suspension_history JSON` + `idx_users_suspended` (037), `POST /users/{id}/suspend|unsuspend` with audit, blocked in `AuthMiddleware`. Instance suspension mirror (038).
15. **Self-service hardened auth (MeAuth)** — `GET+PUT /api/me/auth` (`me_auth_handler.go`) — user picks which authority providers their login must satisfy within `admin-enabled ∩ role-allowed` intersection + how many required. Plain `AuthMiddleware` (any authenticated user).
16. **User profiles (Discord-style)** — `users.display_name,bio,pronouns,accent_color,avatar_symbol,avatar_mime,avatar_filename,banner_mime,banner_filename,social_links` + disk `<datadir>/users/<id>/` (018), `GET /me/profile` + `PUT` with field-level enforcement (umbrella `VIEW_ACCOUNT` implies all; handler rejects fields the narrowed sub-cap lacks), `POST+DELETE /me/avatar|banner` stream multipart MIME validation, `GET /users/{id}/profile` (email redacted) + `GET /{id}/avatar|banner` public 204 when none, `shared/components/ui/Avatar.tsx`, `MarkdownBio`, `SocialIcons`.
